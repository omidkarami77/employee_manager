# مدیریت کارکنان

برنامه Flutter Windows اطلاعات کارکنان را از Collection موجود `employees` در PocketBase دریافت می‌کند. اطلاعات کارکنان محلی ذخیره نمی‌شوند؛ فقط نشست ورود با ذخیره‌سازی امن سیستم‌عامل نگهداری می‌شود.

آدرس پیش‌فرض در [PocketBaseConfig](lib/config/pocketbase_config.dart) قرار دارد. پس از اجرای PocketBase، برنامه را اجرا کنید:

```powershell
flutter pub get
flutter run -d windows
```

ساخت Windows به ابزارهای C++ و مؤلفه ATL در Visual Studio Build Tools نیاز دارد؛ افزونه ذخیره‌سازی امن از آن استفاده می‌کند. در صورت خطای `atlstr.h`، مؤلفه `Microsoft.VisualStudio.Component.VC.ATL` را از Visual Studio Installer نصب کنید.

برای اتصال به آدرس دیگری، `--dart-define=POCKETBASE_URL=<server-url>` را به دستور اجرا اضافه کنید.

فیلدهای Collection عبارت‌اند از `first_name`، `last_name`، `national_code_`، `mobile`، `personnel_code`، `job_title`، `department`، `hire_date`، `end_date` و `is_active`. تاریخ‌ها به صورت روز تقویمی ذخیره می‌شوند؛ `end_date` اختیاری است و هنگام فعال شدن دوباره کارمند پاک می‌شود.

ورود از Auth Collection به نام `users` با ایمیل و رمز عبور انجام می‌شود. `AuthRepository` و `AuthCubit` حالت‌های initial، loading، authenticated، unauthenticated و error را مدیریت می‌کنند. احراز هویت و EmployeeRepository یک PocketBase client و AuthStore مشترک دارند. هنگام شروع برنامه، نشست ذخیره‌شده با `authRefresh` از سرور اعتبارسنجی می‌شود؛ نشست آفلاین یا نامعتبر اجازه ورود نمی‌دهد. نقش در بازگشت به برنامه و هر پنج دقیقه بازخوانی می‌شود. خروج، AuthStore و ذخیره امن نشست را پاک می‌کند و صفحه‌ها و فرم‌های باز کارکنان بسته می‌شوند.

برای راه‌اندازی روی یک PocketBase دیگر، ابتدا از دیتابیس بکاپ بگیرید و فایل [مهاجرت احراز هویت](pb_migrations/1788739200_employee_auth.js) را در `pb_migrations` همان سرور کپی کنید. با راه‌اندازی مجدد PocketBase مهاجرت اعمال می‌شود. اگر از `migrate up` استفاده کردید، پس از آن سرور را مجدداً راه‌اندازی کنید تا قواعد جدید بارگذاری شوند. این مهاجرت برای PocketBase 0.40.x آزمایش شده و فیلدهای کارکنان، از جمله `national_code_`، را تغییر نمی‌دهد. مهاجرت برگشت خودکار ندارد تا ناخواسته دسترسی عمومی مجدداً باز نشود؛ بکاپ را برای بازگردانی نگه دارید. [مستندات migrations](https://pocketbase.io/docs/js-migrations/)

برای **اولین ورود**، در پنل مدیریت PocketBase (`http://127.0.0.1:8090/_/`) به `users` بروید و یک Record با `name`، `email`، رمز انتخابی خود و `role=admin` ایجاد کنید. کاربران عادی را با `role=user` بسازید. حساب superuser پنل PocketBase با حساب admin نرم‌افزار متفاوت است. هیچ حساب یا رمز پیش‌فرضی ایجاد نمی‌شود. ایجاد حساب و تغییر نقش فقط از پنل superuser انجام می‌شود؛ ثبت‌نام عمومی و تغییر نقش توسط خود کاربر بسته است.

| دسترسی | admin | user |
| --- | --- | --- |
| Dashboard، مشاهده، جستجو و جزئیات کارکنان | بله | بله |
| گزارش‌ها و Excel | بله | بله |
| افزودن، ویرایش و حذف کارکنان | بله | خیر |
| تنظیمات | بله | خیر |

محدودیت تغییر کارکنان علاوه بر UI، در Controller، Repository و API Rules سرور اعمال می‌شود. نقش فقط `admin` یا `user` است و نقش خالی/ناشناخته مجاز نیست. نشست به آدرس سرور وابسته است و رمز عبور ذخیره نمی‌شود. بسته‌های جدید این بخش `flutter_bloc` و `flutter_secure_storage` هستند. [مستندات API Rules](https://pocketbase.io/docs/api-rules-and-filters/)

فرم تکراری بودن کد ملی و کد پرسنلی را در لیست دریافت‌شده بررسی می‌کند و خطاهای اعتبارسنجی سرور را نیز نشان می‌دهد. برای تضمین یکتایی هنگام ثبت هم‌زمان از چند برنامه، این دو فیلد باید در دیتابیس نیز دارای ایندکس یکتا باشند.

صفحه «گزارش‌ها» از همان `EmployeesController` و Repository مشترک استفاده می‌کند. حداقل سابقه (همه، ۵، ۱۰، ۱۵ و ۲۰ سال)، وضعیت همکاری و جستجوی نام، نام خانوادگی، کد پرسنلی یا کد ملی به‌صورت ترکیبی و لحظه‌ای اعمال می‌شوند. سابقه با utility موجود تا امروز یا تاریخ پایان همکاری محاسبه می‌شود.

«خروجی Excel» فقط نتایج فعلی را با تاریخ شمسی، ستون‌های فارسی و جهت راست‌به‌چپ صادر می‌کند. کدها و شماره موبایل متن هستند تا صفر ابتدایی حفظ شود. بسته‌های `excel` و `file_selector` فایل `employees_report_YYYY-MM-DD.xlsx` را با پنجره انتخاب محل ذخیره Windows ایجاد می‌کنند؛ انصراف از پنجره فایلی نمی‌سازد. بعد از افزودن افزونه، برنامه را کامل متوقف و دوباره اجرا کنید. اگر Flutter خطای symlink داد، Developer Mode ویندوز را فعال کنید.

تست‌ها از پاسخ‌های شبیه‌سازی‌شده استفاده می‌کنند و دیتابیس واقعی را تغییر نمی‌دهند:

```powershell
flutter test
flutter analyze
```

آزمون واقعی ورود و سطح دسترسی یک PocketBase موقت با حساب‌ها و رمزهای تصادفی ایجاد می‌کند و به دیتابیس فعلی دست نمی‌زند:

```powershell
python tool/test_pocketbase_auth.py C:/pocketbase/pocketbase.exe
```
